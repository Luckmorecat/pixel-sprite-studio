# Animate Pixel Sprite

Read `references/runtime.md` before using tools or scripts; installation does not supply the required execution capabilities.

Animate the accepted native pixels. Own motion, timing and playback without silently redesigning identity or refining the master. The canonical result is unchanged native PNG drawings plus an explicit millisecond timeline; GIFs, sheets and viewers are derived playback artifacts.

## Establish the run and mode

Read `references/project-contract.md`. Check the supplied artifact bundle, then inspect actual accepted native master(s), identity/profile, optional views, action-readiness and approval evidence. A study is not a native master. Resolve missing native acceptance through `refine-pixel-art`; request only missing approvals/choices that block progress. Reconstruct a fresh-session task from the portable bundle and ordinary request, never hidden parent instructions or conversation history. Continue one frozen version, ledger and remaining counters through `references/run-records.md`.

Select task mode: **complete-loop** for a requested animation; **single-cel** for one new drawing; **reuse-existing-poses** when only assembly is requested. Complete-loop carries the task through missing artwork and playback review, not just a plan or one cel. Do not generate new artwork in reuse mode without authorization. Keep absent semantic phases explicit.

Select motion mode before generation:
- **local**: predeclare bounded native rectangles and/or a shaped binary mask covering the whole original moving part, its intended motion envelope and vacated/erased area; copy generated RGBA only there, preserving every outside pixel exactly. Use the schema-2 coverage contract and `local_motion_review.py preflight` before locking it. Inspect native and nearest-neighbor previews on white, dark and checker backgrounds. Exact protected pixels can contain an unwanted remnant, so inspect just outside the mask too. Do not enlarge the mask afterward to hide drift
- **full_body**: permit articulated changes across the body. Preserve identity/style, camera, root/anchor convention, ground contact and apparent scale under declared tolerances; do not impose exact stationary-body pixels, local masks or identical silhouette boxes. Use `references/full-body-motion.md`

Keep native dimensions, palette roles/limit, alpha, padding and user limits fixed. A delegated finished-artifact task may allow assistant acceptance of necessary native/pose gates unless the user reserves a checkpoint. Record assistant acceptance under quoted delegation, never user approval of unseen pixels.

## Plan drawings separately from timing

1. Name the observable action and minimum semantic phases. A page turn needs distinct visible material/hand interaction; a raised hand, blink or body bob does not substitute. Read `references/action-continuity.md` for linked actions and fill its role/contact contract. For full-body cycles, define contact/passing/extreme poses and foot-ground/root behavior appropriate to the requested motion.
2. Choose the smallest distinct drawing set that makes the action readable within the budget. Separately choose ordered timeline entries and holds. Native PNG identity is decoded RGBA, not filename. Repeated holds/reused drawings do not become new drawings. Use the accepted master as rest where appropriate; declare a loop-boundary return instead of assuming matching endpoints means smooth motion.
3. Write `pose-plan.json` from the template, including project reference, motion mode, semantic IDs, expected source/status, timeline order and durations. Use multiples of 10 ms for exact GIF timing. Set phase-readability criteria, contact/occlusion rules, native constraints and shared budget allocation before generating. Missing mandatory phases are not optional embellishments.
4. Generate the hardest distinctive primary-action key first as a viability test. Reserve bounded repairs for its recognition/continuity before easy independent motions. Do not spend the full budget without first checking the action is viable. Count all failed calls and repairs across sessions/stages; no hidden cap reset.

## Generate, normalize and accept each new drawing

5. Use `scripts/native_reference.py` to create an exact integer nearest-neighbor enlargement of the accepted native master. Inspect it. Supply that enlargement as the **primary imagegen identity/pixel reference**, keeping linkage to the original native PNG hash. Add relevant accepted native neighboring/action key enlargements for continuity. Concept imagery and view studies may be supplementary, never substitutes for the accepted native master. For each call state roles explicitly and inspect all local image inputs first.
6. Log generation-start before calling imagegen, with exact prompt/arguments/reference roles/hashes. Request one intended pose per call with locked identity, proportions, outfit/palette roles, camera and required contacts. First key and repairs may use master plus approved supporting references; subsequent dependent phases need the accepted action key/neighbor as well as master. Do not generate every linked phase independently from rest or chain solely from the last generated image. Specify which original limb moves or is occluded to avoid duplicate anatomy and accidental hand switching.
7. Preserve original returned rasters; inspect actual dimensions and grid/crop geometry. A large native enlargement does not guarantee the model returns the same dimensions or cells. Normalize with `prepare_pixels.sh --project project.json`, approved palette and measured fixed geometry; see `references/pixel-tooling.md`. Use a valid grid lock where actual source geometry matches. If a new source geometry differs, reject or establish a documented equivalent full-canvas transform from measurement without independently trimming/recentering. Never stretch a wrong aspect or hide misalignment by shifting a pose.
8. For local motion, confirm the generated key’s actual moving envelope and erased old pose fit the declared coverage, then compose only the predeclared generated regions with `assemble_generated_patches.sh`. Optional shaped masks avoid broad rectangular corner leakage. Exact outside-mask preservation is technical evidence only; first check candidate landmarks/contact alignment, then compare master→key and neighboring composites at native and integer size on white, dark and checker backgrounds using `local_motion_review.py compare`. Inspect the full original moving part, newly vacated area, inside/outside boundary, stray components and attachment seams. Connected-component and delta reports are alerts, not semantic proof. A declared source/envelope/vacated footprint outside the effective selection is undercoverage and blocks acceptance. Do not spend futile regeneration calls or silently widen the mask; preserve the failed plan/evidence and report the need for a separately documented replan. Require a concrete hash-bound coverage review before accepting local phase/adjacent-pair readiness; a tool exit code cannot assert it. No procedural drawing or manual cleanup. For full_body, keep the whole normalized drawing and evaluate identity/root/contact/scale; never use local patching as a full-body shortcut.
9. Inspect native phase readability and newly formed adjacent pairs/triples before accepting. Reject required-phase duplicates, broken material/contact chains, unexplained support-role switches, added limbs, palette-role swaps, identity drift or unclear action. Repair only within the documented caps, using the accepted neighbor and exact failed criterion. Retain every rejected source. At the cap, report `needs_revision`/incomplete with evidence instead of approving a failure to advance.

## Package and review actual playback

10. Fill accepted native paths/status/approval evidence in the pose plan. `pixel_pipeline.py plan` validates all pose references and exports a fresh package; `pack` accepts a direct frame manifest. Shared config contradictions must fail. A draft plan may name not-yet-generated poses, but packaging may not silently skip them. Read `references/pixel-tooling.md` for supported commands.
11. Inspect technical QA: native dimensions, binary alpha, palette union, margins, exact/max counts and duration, unique RGBA drawings, transitions and last→first deltas, protected local pixels or full-body declared geometry evidence, master/source hashes and decoded GIF fidelity. A passing helper cannot certify identity, action or appealing motion.
12. Follow `references/visual-review.md`. Inspect every native drawing and transition including wraparound, the indexed contact sheet, and intended-speed playback at native size and integer enlargement. Distinguish launched playback, sampled screenshots and actually observed full-loop playback. Mark unavailable evidence `unverified`. Review face/identity, articulation/contact, flashes/jitter, spacing/holds, mask seams or full-body footing and closure. Static pose inspection alone is not playback review.
13. Timing/order changes are allowed when within the accepted action/limits; record old/new timeline and export a new version. Artwork changes still use imagegen and count against caps. Never hand-edit art, change skill instructions or add parent rescue instructions inside a frozen trial. Failed technical or visual criteria remain visible.

## Deliver and preserve

State native size, timeline entries, unique drawings, loop duration, budget used, technical status, visual findings/evidence level and unresolved limitations. Deliver native PNGs, timeline/timing, sheet/contact sheet, GIFs/viewer, QA, provenance and self-contained bundle via `references/portable-handoff.md`. Add the complete playback directory as a support tree so HTML, timing and relative sequence links survive relocation; do not flatten linked viewer files into separate hashed names. Overall success requires the requested action, honored constraints and adequate actual playback review; technical pass alone is not success. Preserve the accepted master byte-for-byte.

For an isolated trial, finish/report the frozen version before any general improvement. At most the authorized bounded revision pass may follow the complete validation matrix; retest separately with a new snapshot and ordinary request. Never replace original trial results or claim full-body capability was artistically validated by synthetic tests.
